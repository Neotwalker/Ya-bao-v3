# Product data contract — этап 50

Эта папка фиксирует контракт данных будущего интернет-магазина. На этапе 50 интерфейс сайта не меняется и реальные товары не подключаются.

## Файлы

- `products.schema.json` — JSON Schema Draft 2020-12 для набора товаров;
- `products.json` — 10 синтетических demo-сущностей для фронтенд-разработки и QA;
- `qa-stage50.txt` — результат проверки этапа.

## Базовая структура набора

```text
schema_version
  dataset
  currency
  generated_at
  products[]
```

Каждый товар обязательно содержит системные поля:

```text
external_id
sku
slug
type
status
name
category
sale_mode
price
stock_status
images
updated_at
is_demo
```

`external_id` и `sku` — постоянные идентификаторы для будущей синхронизации. `slug` отвечает только за URL и не должен использоваться как ключ импорта.

## Типы и режимы продажи

### Чай

- `type: tea`;
- `sale_mode: weight`;
- `min_weight_g: 50`;
- `tea_form: loose | pressed`;
- `variants` содержит только доступные для выбора весовые варианты;
- вес варианта — от 50 г и кратен 50 г;
- у каждого варианта есть постоянный `variant_id` и собственная цена;
- если весь товар закончился, `stock_status: out_of_stock`, а `variants` пуст.

Для весового товара верхнеуровневый `price` — цена «от», используемая карточкой каталога и сортировкой. Для товара в наличии она должна совпадать с минимальной ценой доступного варианта.

### Посуда и аксессуары

- `type: ware | accessory`;
- `sale_mode: unit`;
- `quantity` — текущий штучный остаток;
- при `stock_status: out_of_stock` значение `quantity` равно `0`;
- дополнительные варианты допускаются через `variants`, но не обязательны.

## Статусы

- `active` — товар продаётся;
- `out_of_stock` — временно нет в наличии, запись сохраняется;
- `inactive` — скрыт из каталога без удаления;
- `missing_from_feed` — отсутствует в свежей выгрузке и требует проверки;
- `archived` — осознанно снят с продажи.

`status` описывает жизненный цикл записи, `stock_status` — текущее наличие. Это разные поля.

## Редакторские данные

Опциональный `editorial` зарезервирован для SEO title, meta description, длинного описания, вкуса/аромата, заваривания и связанного контента. Эти данные не относятся к автоматическому sync-контракту и в будущем не должны перезаписываться импортом без отдельного разрешения.

`images` оставлен обязательным системным полем, но в demo-наборе массивы пустые: реальные фотографии и реальный ассортимент на этапе 50 не выдумываются.

## Demo-защита

В `products.json`:

- `dataset: demo`;
- у каждого товара `is_demo: true`;
- у каждого товара есть `demo_note`;
- все `external_id`, `sku` и названия явно имеют префикс/маркер DEMO.

Этот файл нельзя использовать как production-ассортимент.

## Что намеренно не входит в этап 50

- `/shop/` и карточки товаров;
- навигация «Магазин»;
- поиск, фильтры и сортировка;
- корзина и localStorage;
- checkout;
- WooCommerce;
- реальный источник CSV/XLSX/Google Sheets/1С/МойСклад/API;
- импорт и синхронизация.

Следующий этап использует этот контракт как основу, но не меняет его задним числом без отдельного решения.
