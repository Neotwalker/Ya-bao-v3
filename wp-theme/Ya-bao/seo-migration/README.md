# Этап 44 — миграция URL и карта 301

Эта папка — инструкция для переноса текущей статической вёрстки на WordPress. Она **не включает активные редиректы в GitHub Pages**: GitHub Pages остаётся превью с `.html`, а правила применяются при подключении production-домена и WordPress.

## Что лежит внутри

- `redirect-map.csv` — точная карта старых `.html` URL и удаляемых `/reviews/`, `/faq/` на финальные clean URL.
- `internal-url-rewrite.csv` — все варианты внутренних ссылок, найденные в текущей статической сборке, и их будущие WordPress-эквиваленты. Включены query/fragment варианты для фильтров меню и пагинации.

## Правила миграции

1. На production все индексируемые страницы открываются только по clean URL с завершающим `/`.
2. Каждый старый `.html` URL отдаёт **один 301** сразу на финальный адрес. Не строить цепочки `html -> промежуточный -> final`.
3. Query string сохраняется. Пример: `/menu.html?category=gaba` -> `/menu/?category=gaba`.
4. `/reviews.html` и `/reviews/` -> `/#reviews`; `/faq.html` и `/faq/` -> `/#faq` согласно утверждённой архитектуре.
5. `article.html` и `event.html` — шаблонные страницы статической версии, не отдельные production URL. Если они были доступны поисковикам, редиректить на `/blog/` и `/events/`.
6. `404.html` **не редиректить**. WordPress должен возвращать реальный HTTP 404 на несуществующем URL.
7. После переноса заменить внутренние `.html` href на clean URL. Не оставлять внутренние ссылки, которые сначала проходят через 301.
8. Canonical, sitemap, robots и schema окончательно переводятся на production-домен в этапе 45. На этом этапе подготовлена URL-логика, но статическое GitHub Pages превью намеренно не ломается.

## Проверка после интеграции на WordPress

- старый URL отвечает 301, конечный URL — 200;
- не более одного перехода редиректа;
- `/menu/?category=...` сохраняет фильтр;
- внутренние ссылки ведут сразу на clean URL;
- `.html` URL не попадают в sitemap и canonical;
- `/404/` или любая несуществующая страница возвращает HTTP 404, а не 200/301 на главную;
- `/reviews/` и `/faq/` не индексируются отдельными страницами после переноса.
